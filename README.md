# Shopping Cart API (Go REST Service)

Реализация REST API для управления корзиной интернет-магазина. Проект выполнен в качестве демонстрационного/тестового задания для демонстрации навыков проектирования чистой архитектуры, работы с СУБД Postgres без ORM и контейнеризации приложения.

---

##  Технологический стек & Архитектурные решения

* **Язык разработки:** Go 1.22+
* **HTTP Роутер:** Стандартный `net/http` (использование встроенных возможностей маршрутизации Go 1.22 без сторонних фреймворков).
* **База данных:** PostgreSQL 16
* **Взаимодействие с БД:** `sqlx` (ручные SQL-запросы повышенной сложности, изоляция транзакций, отказ от ORM в пользу производительности).
* **Миграции БД:** `goose` (миграции встроены непосредственно в бинарное приложение через `embed.FS` и применяются автоматически при старте).
* **Конфигурация:** `viper` (структурированное чтение файлов конфигурации `.yaml` и поддержка переменных окружения/ENV).
* **Контейнеризация:** Docker & Docker Compose (многоэтапная сборка `Dockerfile` для минимизации размера итогового образа).
* **Тестирование:** `testify` (Unit-тестирование граничных условий и валидации).

---

##  Бизнес-логика и ограничения (Бизнес-правила)

В соответствии с техническим заданием в сервисе жестко зафиксированы следующие правила:
1. **Ограничение емкости:** В одной корзине может находиться не более **5 уникальных товаров**. Ограничение проверяется строго внутри ACID транзакции на уровне БД для исключения состояния гонки (Race Condition).
2. **Валидация данных:** Попытка добавить товар с пустым именем или неположительной ценой (`price <= 0`) блокируется как на уровне валидации HTTP-слоя, так и на уровне `CHECK` констреинтов в PostgreSQL.
3. **Изоляция сущностей:** Создание объектов `CartItem` происходит только через привязку к существующей корзине, удаление корзины каскадно удаляет все её элементы (`ON DELETE CASCADE`).

##  Быстрый запуск (Quick Start)

Для запуска приложения вам понадобятся установленные `Docker` и `Docker Compose`. Никаких дополнительных утилит и Go-окружения на локальной машине не требуется.

### 1. Клонирование репозитория
```bash
git clone https://github.com/1of-avangard/cart-api
cd <название-репозитория>
```

### 2. Запуск инфраструктуры и приложения
Команда соберет Go-приложение внутри Docker, поднимет контейнер с PostgreSQL, дождется прохождения Healthcheck базы данных, автоматически применит миграции `goose` и запустит сервер на порту `:3000`.
```bash
docker-compose up --build
```

### 3. Запуск тестов (локально)
Если у вас установлено Go-окружение, вы можете запустить unit-тесты следующей командой:
```bash
go test -v ./...
```

##  Примеры API Запросов (Инструкция по тестированию)

Вы можете протестировать работу API с помощью утилиты `curl` или импортировать эндпоинты в Postman.

### 1. Создание новой корзины
* **Запрос:** `POST http://localhost:3000/carts`
```bash
curl -X POST http://localhost:3000/carts -d '{}'
```
* **Ответ (201 Created):**
```json
{
  "id": 1,
  "items": []
}
```

### 2. Добавление товара в корзину
* **Запрос:** `POST http://localhost:3000/carts/1/items`
```bash
curl -X POST http://localhost:3000/carts/1/items \
  -H "Content-Type: application/json" \
  -d '{"product": "Shoes", "price": 2500.50}'
```
* **Ответ (200 OK):**
```json
{
  "id": 1,
  "cart_id": 1,
  "product": "Shoes",
  "price": 2500.5
}
```

### 3. Просмотр корзины
* **Запрос:** `GET http://localhost:3000/carts/1`
```bash
curl -X GET http://localhost:3000/carts/1
```
* **Ответ (200 OK):**
```json
{
  "id": 1,
  "items": [
    {
      "id": 1,
      "cart_id": 1,
      "product": "Shoes",
      "price": 2500.5
    }
  ]
}
```

### 4. Удаление товара из корзины
* **Запрос:** `DELETE http://localhost:3000/carts/1/items/1`
```bash
curl -X DELETE http://localhost:3000/carts/1/items/1
```
* **Ответ (200 OK):**
```json
{}
```

##  Структура проекта

Код организован по принципам разделения ответственности (Separation of Concerns):
* `cmd/api/main.go` — точка входа, конфигурация ресурсов, инициализация подключений и запуск миграций.
* `internal/handler/` — HTTP-слой, разбор входящих DTO, валидация полей (пустое имя, цена), формирование JSON-ответов.
* `internal/repository/` — Слой хранения данных. Работа с транзакциями, сырые SQL-запросы (`SELECT`, `INSERT`, `DELETE`).
* `db/migrations/` — SQL-файлы миграций для утилиты `goose`.
